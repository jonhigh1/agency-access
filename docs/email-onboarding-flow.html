After the click: the client journey

Intake Platforms Finalizing Complete

Entry

The link lands on /invite/[token]. Two legacy aliases, /authorize/[token] and /client/[token], redirect to it. The landing state resolves by precedence: terminal code → completed → OAuth return → Meta checklist resume → all connected → has progress → intake.

Intake

With intake fields, the client gets a “Quick Setup” form (“Share a few details before authorization.”) and a “Continue” button. Without fields, a “Requested platforms” grid and “Continue to connect”.

Platforms: one loop per platform

Each requested platform runs the same three-step wizard before the request can finalize:

1 · Connect → 2 · Choose accounts to share → 3 · Done
10 platforms · OAuth
  • google · meta · google_ads · ga4 · meta_ads · meta_pages · tiktok · linkedin · snapchat · instagram
  • Google riders ride the parent consent, no own step: tag_manager · merchant_center · search_console · business_profile
  • Exit note: “You will leave for {platform} and come right back here.”
  • Done step shows “Signed in”: “Finish the steps below to share access with your agency.” Meta adds its grant checklist.
7 platforms · Manual invite
  • kit · mailchimp · pinterest · klaviyo · shopify · zapier · beehiiv
  • Step 1: “Resume {platform} setup” — “This platform uses native invite steps instead of OAuth.”
  • Email quartet checklist: copy-invite-email → open-team-settings → send-invite
  • Pinterest: open-business-manager → add-partner → assign-permissions
  • Shopify ends connected — “Submitted for review”
  • Gate: checkbox “I invited {email} to my {platform} account”

Security summary adapts to the mix: “You will authorize access through each platform’s official login screen. Your credentials stay with the platform.” / “You will invite your agency through each platform’s own settings. No login credentials are shared.”

Progress vocabulary: no bar, no counter

done
“Access confirmed.”
action-needed
“Choose which {platform} accounts to share.”
waiting-on-agency
“Your {platform} access request was recorded. Your agency will verify it before this request can finish.”
connect-first · attention
Per-reason copy; status always pairs text with color.

Resume

Progress persists in sessionStorage key invite-progress:{token} merged with the server’s completedPlatforms. An OAuth return (?step=2&connectionId=…) resumes the same connection; no second OAuth. Any recorded progress lands back on platforms, never on intake.

Finalizing

“Confirming your authorization”: “Your connected platforms are being confirmed with the agency.” The page posts /api/client/:token/complete.

Complete

“All set — you’re done” — “{agency} now has access to the accounts you approved. Nothing else is needed from you.” + “You can safely close this window.” Agency-verified variant: “{agency} now has verified access”.

Dead ends

Expired
“This link has expired” — “This access request expired, so access cannot be granted. Contact your agency to get a new link.”
Revoked
“This request was revoked” — “Your agency withdrew this access request. Contact them if this does not look right.”
Unknown
“This link is no longer available” — “We could not find this access request.”
All three
“You can safely close this page.” + a “Need a new link?” support card. Terminal is one-way.

This email does not exist in the codebase

Requests expire 7 days after creation. Expiry is enforced lazily — the first client route hit after expiresAt returns REQUEST_EXPIRED, and a cleanup job deletes the request later.

So the client learns of expiry by clicking a dead link and hitting the terminal card. No email warns them; the only mention anywhere is the reminder’s single line, and reminders are manual.

The slot where a “your link expires tomorrow” mail would sit is empty.

Where the emails come from

The agency side that pulls the trigger — creation, delivery, and the callout the agency sees while waiting.

Create
Wizard at /access-requests/new, 4 steps: Fundamentals → Platforms → Customize → Review. Create mints the 12-char token and expiresAt = +7d, status pending.
Deliver
Three ways: Copy Link / Preview; “Send invite” email form (“Invite sent to {email}. Replies go to you.”); or a mailto fallback — “Authorize platform access for {clientName}”.
Wait
The request page shows: “Client invite: Needs you — The client still has steps on the invite link (connect, share, or verify). Tokens are stored only after they finish — not when the link is sent.”
Docs drift
docs/APP_OVERVIEW.md calls the same 4 steps “Client Info / Platforms / Intake Form / Branding” — labels and order no longer match the code (G3).
