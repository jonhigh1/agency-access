1

Connect

Route depends on the platform's connection method: oauth · manual · api_key
OAuth platforms

Meta, Google (Ads + GA4), LinkedIn, TikTok, Snapchat, Instagram.

Redirect to platform→ Client signs in + consents→ Callback (state verified)→ Connection created

Google Ads may fall back to a native grant: manager link or user invite.

Manual / API-key platforms

Kit, Beehiiv, Mailchimp, Pinterest, Klaviyo, Shopify, Zapier.

Exact in-platform instructions→ Client invites / pastes API key→ AuthHub verifies→ Confirmed

No OAuth redirect — the client does it inside the platform; AuthHub generates the steps.

2

Choose accounts to share

Assets fetched live from the platform after connect
Asset selector→ Meta: ad accounts · pages · catalogs→ Google: ads accounts · GA4 properties→ LinkedIn · TikTok: ad accounts

Nothing found? Create it inline: Meta business setup checklist + asset creator, with proof steps (page engagement, dataset verify). Selection resets require confirmation. Saved to grantedAssets (row-locked write) + metadata.selectedAssets.

3

Done — grants & checklist

Server truth: checklist renders from the backend, not local state
Grant checklist (Meta system-user / asset grants)→ Verify each item→ All green → platform complete

Declining a declinable asset doesn't block the flow — the agency sees the gap. Leaving mid-wizard is safe: progress is saved per platform and the link resumes where the client left off (?connectionId=…&step=2).

completed

Every requested platform authorized. Agency notified.

partial

Some platforms done. Reminders fire; agency can nudge.

expired

7 days elapsed. Agency re-issues in one click.

revoked

Agency or client revokes; tokens deleted from Infisical.

Behind the scenes — token lifecycle

What happens in the seconds after a client clicks "Allow" — and forever after.

01Consent returns

Platform redirects back with code + state.

→
02State check

OAuthStateService validates single-use CSRF state in Redis.

03Token exchange

Connector swaps code for tokens. Meta: 60-day long-lived exchange. Google Ads: developer-token header.

04Seal in Infisical

Tokens written to Infisical secrets management. Never to PostgreSQL.

→
05Reference row

Postgres stores only secretId + selected / granted assets.

→
06Audit

AuditLog entry: user email, IP, user agent, action, timestamp.

07Refresh loop

BullMQ worker keeps tokens alive on a schedule.

→
08Health watch

healthy → expiring → expired. Agency sees reconnect prompts before breakage.

→
09Serve

Agency pulls assets / connections; tokens fetched from Infisical only when needed.

✓ Tokens never touch PostgreSQL ✓ Every token access audited ✓ CSRF state: Redis, single-use ✓ Agency-scoped queries, always ✓ Infisical identity rotated quarterly
E

AI agent operations

The newest surface: external AI agents (via MCP) operate on platform access — but only inside scoped grants, gated policies, and with human approval on risky steps.

1 · Register the agent

Agency creates a grant: OAuth client id + display name.

2 · Scope it

Permission list + risk class. Owners only (admin gate).

3 · Gate it

Policy rules + rollout percentage control what agents may attempt.

4 · Let it work

Agent authenticates and drives operations through MCP tools.

Operation state machine
prepared→ pending_approval→ approved→ executing→ succeeded
failed_retryable↺ re-queued failed_terminal declined expired canceled
Completion states
completed partial follow_up_needed pending · expired · revoked · invalid

Every operation lands in /agent-operations with full activity and telemetry; a retention service prunes history. Access-request grants can also be issued to agents — same audit trail as human clients.
